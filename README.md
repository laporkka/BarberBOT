# BarberBOT 💈

**BarberBOT** — это асинхронное B2B SaaS-решение для автоматизации онлайн-записи и управления расписанием в барбершопах. Проект построен на базе микросервисной контейнеризированной архитектуры, разделяющей ядро бизнес-логики (REST API) и пользовательский интерфейс (Telegram-бот).

Главная технологическая особенность системы — **динамическая побитовая карта времени (Time Bitmap)**, обеспечивающая мгновенный поиск свободных окон под любую длительность услуг и гибкий график работы салона без тяжелых SQL-запросов.

---

## 🔥 Ключевой функционал по ролям

Система автоматически определяет роль пользователя по его Telegram ID при запуске (`/start`) и предоставляет изолированный интерфейс:

### 1. 📱 Клиентский интерфейс
* **Пошаговое бронирование (CJM):** Выбор мастера ➔ Выбор услуги ➔ Динамический календарь на 7 дней ➔ Сетка свободных слотов, рассчитанная по битовой маске.
* **Сбор контактов в 1 клик:** Безопасная передача номера телефона через нативную reply-кнопку Telegram (`request_contact=True`).
* **Личный кабинет («Мои записи»):** Просмотр актуальных бронирований с локализованными статусами визитов.
* **Прайс-лист:** Просмотр активных услуг, их стоимости и длительности напрямую из базы данных.
* **Умная навигация:** Поддержка кнопок «Назад» и «Отмена» на каждом этапе бронирования.

### 2. ✂️ Интерфейс Мастера (Барбера)
* **Актуальное расписание:** Просмотр списка записанных клиентов на «Сегодня» и «Завтра» с указанием точного времени и контактных телефонов.
* **Автоматическая защита доступа:** Если профиль мастера деактивирован управляющим, система мгновенно ограничивает доступ к рабочему расписанию.

### 3. 📊 Интерфейс Управляющего (Админ-панель)
* **Оперативная сводка («Загрузка салона»):** Аналитика занятости всех мастеров на текущий день в реальном времени.
* **Динамический график работы салона:** Настройка часов открытия и закрытия индивидуально для каждого дня недели (Пн–Вс), переключение выходных дней и массовое применение единого шаблона ко всей неделе.
* **Управление персоналом:** Добавление новых мастеров по Telegram ID, редактирование имен и мягкое отключение (`Soft Delete` через флаг активности) без потери истории записей.
* **Управление прайс-листом:** Создание новых услуг, изменение цен и управление видимостью позиций для клиентов.

## 🛠️ Технологический стек

* **Backend:** FastAPI, Pydantic v2, SQLAlchemy 2.0 (Async), Alembic.
* **Bot Frontend:** Aiogram 3.x (Routers, FSM), HTTPX (асинхронный пул соединений).
* **Базы данных и кэш:** PostgreSQL (основное хранилище), Redis (персистентное хранение состояний FSM).
* **Инфраструктура:** Docker, Docker Compose.

## 🧠 Алгоритм расписания: Динамическая битовая карта (Time Bitmap)

Вместо ресурсоемких SQL-запросов с поиском пересечений временных интервалов используется побитовая арифметика:

1. При запросе свободных слотов сервис получает график салона на конкретный день недели из таблицы `work_schedules` и проверяет флаг `is_working_day`.
2. Границы рабочего дня переводятся в минуты от начала суток, и динамически вычисляется общее количество 30-минутных слотов (`total_slots`).
3. Весь рабочий день кодируется в памяти как целое число (`bit_map = 0`). Существующие записи мастера сдвигают соответствующие биты в единицу (`bit_map |= (1 << idx)`).
4. Для выбранной услуги генерируется битовая маска её длительности («трафарет») и накладывается на карту дня через операцию побитового И (`bit_map & service_mask == 0`). Расчет происходит за наносекунды на уровне процессора.

## 📂 Структура проекта

```text
BarberBOT/
├── app/
│   ├── api/                  # REST API эндпоинты (barbers, services, appointments, schedule)
│   ├── bot/                  # Логика Telegram-бота
│   │   ├── handlers/         # Обработчики сценариев (start, booking, barber, admin)
│   │   ├── keycads/          # Генераторы инлайн- и репли-клавиатур
│   │   ├── utils/            # Изолированный HTTP-клиент (ApiClient на httpx)
│   │   ├── fsm.py            # Машина состояний (BookingState, AdminState)
│   │   └── main.py           # Точка входа, инициализация бота и RedisStorage
│   ├── core/                 # Конфигурация (Pydantic Settings) и подключение к БД
│   ├── models/               # SQLAlchemy-модели таблиц
│   ├── repositories/         # Слой доступа к данным (паттерн Repository)
│   ├── schemas/              # Pydantic-схемы валидации
│   └── services/             # Бизнес-логика (ScheduleService с битовой матрицей)
├── alembic/                  # Миграции базы данных и сидирование начальных данных
├── docker-compose.yml        # Оркестрация контейнеров (api, bot, postgres, redis)
├── Dockerfile                # Сборка образа приложения
└── requirements.txt          # Зависимости Python
```

## 🚀 Быстрый запуск

Для развертывания проекта требуются только установленные **Docker** и **Docker Compose**.

### 1. Настройка окружения
Создайте файл `.env` в корневой директории проекта:

```env
# PostgreSQL
POSTGRES_USER=postgres
POSTGRES_PASSWORD=your_secure_password
POSTGRES_DB=barber_db
DATABASE_URL=postgresql+asyncpg://postgres:your_secure_password@postgres:5432/barber_db

# Telegram Bot
BOT_TOKEN=1234567890:ABCdefGhIJKlmNoPQRsTUVwxyZ
ADMIN_IDS=["5288382067"]
```

### 2. Сборка и запуск контейнеров
Запустите инфраструктуру в фоновом режиме:

```bash
docker compose up -d --build
```

При первом запуске необходимо применить миграции базы данных (таблица расписания автоматически заполнится базовым графиком):

```bash
docker compose exec api alembic upgrade head
```

### 3. Доступ к сервисам
* **Интерактивная документация API (Swagger):** `http://localhost:8000/docs`
* **Telegram-бот:** готов к работе сразу после старта контейнера по команде `/start`.
